# 技能档位插件 · 设计定稿

状态：讨论定稿（未实现）。所有条目均已拍板，唯文末「待定」一节需要确认。

---

## 1. 目标与非目标

**目标**：让同一个 agent 在「日常 / 工作 / 交付」三种登记簿之间切换，使技能目录不再对闲聊施加工作口吻（列表、结论、数字）。切换要可解释、可回滚、可观测。

**非目标**：
- 不做逐技能开关。档位是整体的，不提供「停用 office-xlsx」这种粒度。
- 不为 token 节约而做。目录裁剪是副作用，不是目的。
- 不做多语言适配。中文优先，其他语言由社区自行处理；但**不得把任何具体中文词写进先验**（见 §4.3）。
- 插件永不自己说话（§3.4）。
- 不修改 DSH 宿主代码，不 monkey-patch。

## 2. 档位与角色

### 2.1 三档

| 档 | 目录常驻 | 用法 |
|---|---|---|
| 日常 | 由分类结果决定（可为 0，也可含角色扮演/陪伴/语气类）+ 1 行指路语 | 闲聊、陪伴、情绪对话 |
| 工作 | 诊断、代码、仓库、研究、审查类 | 改代码、查 bug、查资料 |
| 交付 | 产出物相关（表格、文档、图、PDF、渲染） | 出表、出图、出报告、导出 |

**各档具体放哪些技能不由插件写死**，见 §2.4。

指路语（日常档，只有模型能看到）：`工作与文档技能可按需启用，根据用户说要做什么即可。`

### 2.2 五种角色（开放集合）

`enter-work` / `enter-deliver` / `hold` / `exit` / `veto`

- `hold` 是维持信号，**不是**升档信号。「继续」「ok」「开始吧」属于 hold——在聊天里也很常见，当升档用会误切。
- `veto` 是「明确不要切」：「先别动手，仅讨论」「告诉我现在有几个技能」这类看着像任务、实际是讨论的话。
- 新增角色属于结构变更，需要确认（§5.4）。

### 2.3 初始档位

**一律「日常」**。不按来源、不按 cwd、不按 preset 推断。

### 2.4 技能分档（每次清单变化时重建）

档位与技能的对应关系**不写死在插件里**。别人的机器上装的是别人的技能，我这台机器的分类结果没有参考价值。

1. **触发**：安装时 + 每次 `skills/change`（新增、删除、更新）。
2. **输入**：每个技能的 name / description / whenToUse（只读摘要，不读正文，省 context）。
3. **分类**：由模型把每个技能归入 日常 / 工作 / 交付 / 丢弃，每条必须带一句理由。
   - 日常档**允许有技能**：角色扮演、陪伴、人设、语气类技能属于日常，不是工作。
   - 工作档：诊断、代码、仓库、研究、审查。
   - 交付档：产出物相关（表格、文档、图、PDF、渲染）。
4. **失效剔除**：逐个 `get()` 验证。加载失败（YAML 语法错、文件缺失、provider 不可用）→ **丢弃**，不进任何档，并在设置里列出原因。宁可少一条，不列表尸。
5. **不确定 → 问用户**：描述含糊或置信度低时，由模型用当前 agent 的口吻问一句「这个技能你觉得该放哪一档」，答案写入映射并标记 user-confirmed。
6. **产物**：`tiers.json`（skill → tier、理由、置信度、确认来源、生成时间）。
7. 设置里可手动改任意一条；手动改动优先级最高，不参与后续自动分类。
8. **一个技能可以同时属于多个档**（2026-10-29 补）：分类器一次只给一个主档，但 `tiers.json` 的三个数组允许重叠，判断的是「在不在这一档」而不是「属于哪一档」。人工钉死的归属写在 `manual` 里，重跑分类不会覆盖它。
   理由：日常档在开发者机器上常常是空的（22 个技能全是工作/交付型），但别的机器上会有既能闲聊又能干活的技能。

## 3. 状态机

### 3.1 转移

```
日常 ──显式 enter-work / 规则 ──▶ 工作 ──显式或确认 enter-deliver──▶ 交付
  ▲                                │                                   │
  └──── exit / 连续2轮无任务信号 ◀──┘◀───────── 交付完成事件 ───────────┘
```

- 只在**轮边界**切换，一轮之内档位恒定。
- 每次改档后冻结 3 轮（照算不生效），防抖动。
- 升档保守，降档灵敏：升档要求「祈使 + 明确对象 + 结果可验证」三者有其二；降档出现任一闲聊标记即生效。
- **降档以衰减为主**：真实语料里 exit 语句天然稀疏（人不会每次都宣布收工），所以「连续 2 轮无任务信号且无待办」是主要降档路径，显式 exit 只作加速与兜底。
- **升档后 2 轮内工具调用为 0 → 自动回退到原档。**

### 3.2 交付档特殊规则

- 只能由显式请求（图表 / 表格 / 报告 / 交接 / 导出 / PDF）或经确认的提案进入。
- 交付完成（文件生成/发送）后退回**工作**，不回日常。
- 交付中用户插入消息：由**模型**判断是否打断。模型只能降档，不能升档。
- **收尾交付不是交付档**：收工前顺手出一张图、一份交接文件，是一次性动作，不改档位（工作 → 日常直接走）。否则会话会停在交付档上。区分标准：抛出一个持续产出模式（做表、改表、渲染）= 进交付档；一次性的收尾动作 = 规则上的 `action`。

### 3.3 权限矩阵

| 来源 | 升档 | 降档 | 说明 |
|---|---|---|---|
| 用户显式 | 直接生效 | 直接生效 | 最高优先级，不参与打分 |
| 规则（词表 / 先验） | 直接生效 | 直接生效 | 静默 |
| 模型 | **必须先问用户** | 可直接生效 | 降档是保守方向，footer 会闪 |

模型的升档请求走 `mode.request`（目标档 + 一句理由），插件进入 pending，TTL 3 轮；模型用自己的口吻询问，用户同意后 `mode.confirm` 生效。插件不生成任何面向用户的文案。

### 3.4 模型知情（只读暴露）

系统提示常驻一行：`本会话当前档位：日常。` 档位变化后立即更新。模型可读、不可写；其他插件同样只读。

### 3.5 手动锁

用户说「这轮就聊天，别切了」→ 锁档，解除前不自动切换，不参与归纳。锁状态在会话结束时清除。

### 3.6 失败处理

- 插件内部错误 → fail-open：保持当前档，退回「只认显式指令」，footer 显示警告。
- 词表损坏 / 回放集缺失 → 同上，不影响对话。

## 4. 判定流水线

### 4.1 优先级

`用户显式` → `词表（归纳产物）` → `结构先验`。前者命中即短路。

### 4.2 在线成本

每轮**零 LLM 调用**，只做模板/字符串匹配。判不准一律不升档。

### 4.3 结构先验（不含任何具体词）

只用语言学无关特征：句长、是否含路径/扩展名、是否动词开头、是否问句、有无数字单位、是否与上一轮话题重叠。

### 4.4 冷启动

- 前 14 天 / 前 20 个会话：**只降不升**（自动升档关闭）。
- 每会话一次模型判定首句，作为初始档位（每会话一次，非每轮）。
- 首次归纳触发：`≥20 会话` 或 `14 天`，先到先得，之后进入月度周期。
- 首轮 footer 显示「日常档 · 尚未校准」8 秒。
- 可选三问校准（设置项，默认关闭）：用用户自己的话生成 3–5 条种子规则，conf=0.5，首周只影子。

## 5. 归纳与版本

### 5.1 周期

默认 **30 天**，用户可配置。月度归纳**不重置**版本历史；周期变更只影响下一次归纳。

### 5.2 窗口与样本

- 滚动窗口「最近 30 天」，不用自然月。
- 按会话聚类抽样，同一项目最多抽 N 个会话，防止项目词占满窗口。
- 窗口内工作会话 < 阈值 → **跳过本月**，保持上一版（淡季保护）。

### 5.3 跨月稳定性

候选词必须出现在 **≥2 个不同月份**的窗口里，才允许进入 `enter-work`；只在一个月高频出现的，只进「项目词」低置信层。

### 5.4 结构变更的判定

不看改动类型，看**回放翻转率**：在冻结回放集上，判定翻转 > 3% 即视为结构变更。

- 结构变更（新增/合并/拆分/退休角色或族）→ 需确认。
- 词条微调（pattern、示例、置信度）→ 自动生效，但单次调整 ≤0.1，单条累计漂移 >0.3 强制转结构审核。

### 5.5 确认流程（方案 B + 超时放行）

1. 新版本生成 → 不生效，进入**审核窗口**（同时也是影子窗口：旧版生效，新版并行打分，分歧进 diff）。
2. 7 天内用户确认 → 生效。7 天未确认 → 自动生效，diff 标记「未经确认」。
3. 自动生效版本 30 天内可一键回滚；已确认版本 30 天内可回滚（需理由）。

### 5.6 漂移提前触发

一周内 80% 的切换来自显式指令 → 说明词表脱节 → 不等月末，立即跑一次临时归纳。

### 5.7 版本

保留最近 6 版，含：生成时间、样本窗口、回放分数、与上一版 diff（人话版）。

## 6. 词表 schema

```json
{
  "schema": 1,
  "generatedAt": "2026-10-27",
  "windowDays": 30,
  "replayScore": 0.87,
  "roles": {
    "enter-work": [
      { "family": "动作祈使", "pattern": "帮我(看看|查查|搜|开|跑)",
        "pos": ["帮我在 GitHub 搜一下"], "neg": ["帮我想想你自己想做什么"],
        "conf": 0.8, "hits": 12, "lastHit": "2026-10-25", "project": null,
        "requires": null, "action": null }
    ],
    "hold": [
      { "family": "续行", "pattern": "^(好|ok|行)?[，,]?.*继续",
    ],
    "exit": [
      { "family": "收工", "pattern": "(完工|搞定|结束了|先这样)",
        "conf": 0.8, "requires": null, "action": "deliver:summary" }
    ],
    "enter-deliver": [], "veto": []
  }
}
```

约束：活跃规则 ≤ 60 条；每族示例 ≤ 8 条，按时间衰减；每月归纳后旧示例自然退场。

## 7. 存储

用户级 `~/.dsh/mode/`：

| 文件 | 内容 |
|---|---|
| `lexicon.json` | 当前词表 |
| `tiers.json` | 技能→档位映射（含理由、置信度、确认来源） |
| `preferences.json` | 非词表的用户偏好（如「收工时先给简易图表，再问要不要详细版」） |
| `versions/YYYY-MM.json` | 版本快照，保留 6 版 |
| `holdout.jsonl` | 冻结回放集（只读，安装时抽 20%） |
| `overrides.json` | 即时纠正（「别上表格」），归纳前一直有效 |
| `state.json` | 各会话当前档位，供重启恢复 |

不同步到其他机器；支持导出/导入。所有文件带 `schema` 版本。

## 8. UI

**定案：不做自定义 footer。** 档位状态就靠 `/tier` 命令的回显呈现——`>_ tier · 已切到 日常 档，下一轮生效`。这是 DSH 自带的命令行渲染器画的，客户端零代码。

理由：客户端读档位需要把插件骨架改成 service 类 + `@Remote`，为一个提示行换地基不划算；命令回显已经满足“用户知道当前在哪一档”。

代价（已知并接受）：只在敲命令那一刻出现，不常驻。原计划的 footer（消息下方 8 秒橙黄小字、冷启动显示“尚未校准”）取消，不再排期。

另一条代价：**`/tier off` 不会撤回已经注入的那条清单**。插件从此不再改写，但模型历史里那条「以此为准」还在，直到上游重新发布清单（技能有增删）或开新会话。所以「关掉能完全恢复原样」这句话，准确说是「下一轮起不再改写」，不是「立刻清空」。

## 9. 兼容与降级

### 9.1 依赖分层（v0.1 实测后修正）

| 层 | 依赖 | 破了怎么办 |
|---|---|---|
| 稳 | `skills.snapshot({cwd, scope})` | 拿不到就不注入，保持现状 |
| 较稳 | `agent/pre-step` 的 `decision.messages` | 形状变了就退回只认命令、不动清单 |
| **脆** | **注入消息要「深冻结 + 自有 `source.kind`」** | 借用 `skill-catalog` 会被会话层按目录事件消化掉，消息不落盘 |
| 最脆 | 客户端 footer slot（尚未做） | 软挂载，不显示 |

**两条实测规律，写进代码约定：**

1. **轮中注入不落盘**，只有轮首（`step === 1`）那份会进会话历史并被模型看到。所以只在轮首、且档位变过时注入。
2. 注入消息必须 `deepFreeze(structuredClone(...))`、自带 `id`、用**自己的** `source.kind`（`skillgate-tier`）。三条缺一，消息就静默消失——不报错，只是模型看不见。

### 9.2 读历史移出运行时

归纳器是独立进程/命令，不进入运行时依赖。DSH 会话日志格式（`session.v4.jsonl.zstd`，分帧 zstd）变了只影响归纳，不影响切换。

### 9.3 自检与契约测试

- 启动时用 inspect 的 Service/Event 目录做**能力探测**，不硬编码版本号。
- 仓库内维护黄金样本（脱敏会话 + 期望输出：边界位置、归纳族、档位序列）；DSH 更新后先跑它。

### 9.4 周期解耦

DSH 更新不触发归纳；归纳失败不影响运行时判断。

## 10. 命名与遗留

**命名**：插件 `dsh-skillgate`，包名同名，不再缩写。`SG` 只作内部别名、日志前缀和图标缩写。代码里 service 用全称 `skillGate`、事件用 `skillgate/...`——半年后回头看 `ctx.sg`，会让人卡住。

**已定（原待定 1–3）**：
1. 三档的目录构成改为 §2.4 的动态分类，不再写死。
2. `time-estimates` / `domain-modeling` 也不由插件预设；分类器的默认建议是前者丢弃或日常、后者交付，最终以分类结果和用户确认为准。
3. 名称如上。

**仍需在动手前定**：4、5 的答案已补在下文，剩下的只是把数值跑一轮真实数据校准。

### 10.1 结构先验（原 4）

只保留**与语言无关的形状特征**，因为它们不需要读懂句子：

| 特征 | 用途 |
|---|---|
| 字符长度（>30 偏聊天，<8 偏指令） | 权重 |
| 含盘符、路径、URL、`@文件`、扩展名 | 工作 +2 |
| 以问号结尾、疑问句式 | 降档权重 |
| 标点密度（emoji、波浪号、省略号） | 降档权重 |
| 与上一轮消息的字符重叠率 | 维持当前档 |

**限制**：「把那个改成绿的」和「把那首歌改成纯音乐」结构完全一样，光看形状分不出来。所以「是请求还是闲聊」交给模型——冷启动期每会话一次（§4.4），有词表后由词表覆盖。**先验永远不单独触发升档。**

### 10.2 四问校准（原 5）

措辞的目标是引出**用户自己的原话**，而不是让他总结规律。跑过一轮模拟后，三问补成四问：

1. 「你开始让我干活的时候，一般会怎么说？随便举两三句你平时真会说出口的。」→ `enter-work`
2. 「活干完了、或者你想切回闲聊的时候，你会怎么说？」→ `exit`
3. 「有没有哪句话，听起来像在派活，其实你只是想聊天？举一句。」→ `veto`
4. 「你需要我出表格、图、文档、交接文件的时候，一般会怎么说？」→ `enter-deliver`

**模拟结论（一次真实回放，四条共 12 句原话）：**

- 第 1 问有效：6 句里 5 句能直接抽出 pattern，剩 1 句（「这个插件怎么样」）无结构特征，交模型。
- 第 2 问偏稀疏：用户自述「这类很少」。不是措辞问题，是现实如此——**降档必须以衰减为主**（§3.1）。
- 第 3 问会提前收到第 2 问的答案（用户常把「不升档」的句子当收工句给）。
- 第 4 问不只产词表，还会暴露**偏好**：「收工时先给一张简易图表，再问要不要详细版」不是词表条目，进 `preferences.json`，由模型执行、插件只注入提示。

默认不弹，设置里可选。

**实测补记（2026-10-29）**：真让人现编短语编不出来，改成从真实语料里挖——两天 78 句人话，抽出 7 条新规则（进工作 3、退出 2、否决 2），回放里每条只命中自己的出处。三条教训：

1. **照抄原话会抄错半截**：「我要开始忙了」对不上原话「我要开始忙**起来**了」，差一个字规则就永远不触发。归出来的词必须回放到原句上验一遍。
2. **「唠嗑」属于 exit 不属于 veto**：veto 是“别动”，exit 才是“回日常”，语义放错会让它原地待着。
3. **模糊感叹句不猜**：「救救我」三个字无宾语无动作，可能是玩笑也可能是累，规则一律不动，交给 v0.5 的模型判定去问一句。

## 11. 假设登记（防过拟合）

本设计的语料全部来自同一台机器、同一个用户（58 个会话）。凡由单一语料得出的结论，一律标记为**假设**，不得写死成代码常量。

| 结论 | 来源 | 性质 | 验证方式 | 失效时的退路 |
|---|---|---|---|---|
| exit 语句稀疏 | 单用户 12 句 | 假设 | 第二用户首月统计 exit 命中率 | 提高衰减权重，不依赖 exit |
| 收工句很短（≤8 字） | 单用户 | 假设 | 归纳时按用户重算长度分布 | 阈值按人拟合 |
| 交付触发含产出物名词 | 单用户 | 弱普适 | 首月归纳命中率 | 回落到模型判断 |
| 衰减 2 轮 | 未验证（拍定） | 猜测 | 影子日志统计误升/误降 | 可配，首月拟合 |
| 冻结 3 轮 | 未验证（拍定） | 猜测 | 同上 | 同上 |
| 回放翻转率 3% 判结构变更 | 未验证（拍定） | 猜测 | 回放集上试 1% / 3% / 5% | 可配 |
| **换清单会改变语气** | **单用户直觉（本项目的立论）** | **未证实，证据偏否** | 本地 60 条 A/B + 真机两轮，见 `skillgate/AB-2026-10-28.md` | 证伪则把定位降为「控制模型可见技能」，口吻改由提示词层承担 |
| 先验不含具体词 | 原则 | 普适 | — | — |

**五条纪律：**

1. 所有默认值只是**初始值**。首月归纳后必须用该用户自己的数据重新拟合，不允许写死。
2. 词表、偏好永不内置。装完默认是空的，宁可什么都不切。
3. 发布前至少跑四种画像的回放：角色扮演型（日常档有大量技能）、极简型（不用技能）、英文用户、低频用户（月会话 < 10）。
4. 任何"从我的语料看出来"的结论进代码前，先在这里登记一行。
5. 没有第二个人类用户的数据之前，v0.1 只追求「可配 + 可观察 + 可关」，不追求准确。

## 12. 时间感知模块

并入 skillgate，共用同一节设置与同一个 footer。目的是让模型对时间不自造，不是给用户看。

**时钟**
- 以设备系统时间为唯一权威。模型只能读，不能写、不能自行推算。
- 显示用墙上时钟；差值计算用单调时钟；两者偏差 > 5s 时以单调为准并记日志。
- 差值 ≤ 0 按 0 处理（防时钟回拨把「剩 20m」变成「剩 1h20m」）；差值 > 6h 按异常记日志。

**每步注入（用户不可见）**

```
⏱ 23:51:56 · 本会话 1h12m · 上次工具 3s 前 · 截止 00:12（剩 20m）
```

无截止时省略最后一段。「剩 X」由系统算好，模型永不做减法。

注入位置固定在提示末尾、紧贴当前步骤；放到前面会让每一步都使整段前缀缓存失效。

**工具**
- `now()`：返回同一行的即时版本，供它随时校准。
- `set_deadline(after, note)`：只收相对时长，由系统换算成绝对时刻；新截止覆盖旧截止，回执说明被替换。
- `clear_deadline()`：收尾完成后调用。

**漏设兜底**
用户消息含明显时长表达、三步内未设截止 → 给模型一次提示（不打扰用户）。

**到期行为**
软提醒，不强制中断。文案指定动作（「把手上这步做完就停，然后汇报进度与剩余项」），而不是「时间到了」；提醒一次后每 3 步一次，最多 3 次；会话结束自动清除。

**历史时间**
先在本会话日志里做确定性检索（关键词 / 文件名 / 时间范围）；查不到再问用户是否翻历史。不由模型凭印象判断「对不上」。

## 13. 实施边界

原则：**每一版都能独立观察、独立回滚**；先证伪前提，再加能力。v0.1 若证明「换档不改变语气」，整个项目就该停，不必往下做。

### 13.0 先写探针（不动代码，只打印）

两件最脆的东西必须先验：

1. 能否在 `system-prompt/assemble` 里**精确定位并替换**技能清单那一段；替换后模型看到的条数是否正确。
2. 客户端 footer 那一行的 slot 是否存在、能否挂一个自定义行。

探针只读、只打印、不生效。任一条不成立，先解决它，再谈 v0.1。

**实测结论（2026-10-28，推翻了原方案的一半）**：技能清单**不在** system prompt 里（探针 1 扫了 24 个 section、0 次出现），**也不在** `agent/request` 的配置里。它由 `@deepseek-ai/dsh-tool-skill` 在 `agent/pre-step` 里追加成一条 user 消息（`source.kind = "skill-catalog"`），内容来自 `ctx.skills.snapshot()` 过滤 `isModelInvocable` 之后的结果。所以「定位并替换那一段」这条路不存在——改成**轮首追加一条「以此为准」的替换清单**。footer 的 slot 确实存在（`conversation.chat.turnTail`），但客户端读不到 host 状态，见 §8。

### 13.1 版本划分

| 版本 | 包含 | 不包含 | 验收 |
|---|---|---|---|
| **v0.1 骨架** ✅ | 插件包与安装；三档状态（按会话，`state.json` 持久化）；手动切档命令；目录换档；命令回显留痕；fail-open | 任何自动判定、词表、时间、归纳 | 手动切三档，模型分别看到对应清单；重启后档位仍在 |
| **v0.2 时间** ✅ | 每**轮**一行时刻（非每步，见下）、`now`、`set_deadline`、`clear_deadline`、到期提醒 | 历史检索 | 三个工具往返通过；截止状态可读 |
| **v0.3 种子词表** ✅ | 字面匹配五类：`enter-work` / `enter-deliver` / `exit` / `veto` / `hold`；命中即切档并**当轮注入**；手动切档后 10 分钟静默期；`tools/lexicon-stats.mjs` 统计命中与误判 | 四问校准界面、正则归纳 | 双向实测通过；`hold` 需 30 分钟内有干活记录 |

### 13.2 v0.3 已知粗糙处（明早先看这几条）

1. **误判面广**：任何含「帮我…」的句子都会切工作，包括「帮我看看这段感情」。影子日志里的 `rule` 行就是用来量这个的。
2. **规则会盖过手动**：刚 `/tier daily`，下一句命中 `enter-work` 就又被顶上去；还没有「手动优先、N 轮内不被规则覆盖」的锁。
3. **只做了单向**：`hold` 与交付档没有规则；「继续」现在会被忽略（正确），但也可能漏掉真正的续行。
4. **词表是字面匹配**：没有置信度、没有 diff、没有回放验收——那是 v1.0。
5. **注入消息会累积**：每次档位变化在历史里留一条，长会话里要注意体积。

### 13.3 v0.2 的落地偏差（已接受）

§12 原写「每步一行时间」，实测不可行：轮中注入不落盘、也不进请求（同 §9.1 第 1 条）。所以改成：

- **每轮一行**（轮首注入），含本机时刻、本会话时长、截止状态；
- 轮中要精确时刻，模型自己调 `now()`——工具调用不受注入限制；
- 截止提醒也只能落在轮首，所以「40 分钟内做完」这类场景，模型需要在干活的间隙自己调 `now()` 查。这是当前机制的硬限制，不是实现偷懒。

另：时间行只在「有截止」或「距上次时间行超过 10 分钟」时发，避免每轮都塞。

### 13.4 永不做

- 逐技能开关
- 多语言适配（先验不含具体词，但界面只做中文）
- 自动升级 / 遥测
- 修改 DSH 宿主代码

### 13.5 默认姿态

v0.1–v0.4 全部默认「可关、可观察、不写死」：一个开关能立刻退回「只认手动切换」，且切换记录可导出。§11 的五条纪律对每一版都生效。

## 14. 自检记录（2026-10-28 01:10）

**第一轮：假 ctx 驱动器。** `tools/selftest.mjs` 直接驱动 `agent/pre-step`，不启 DSH，23 个用例覆盖判定、注入形状、失败路径。每条新用例都做过变异检验（把代码改回去，用例必须变红）。

抓到并修掉三处：

1. `/tier on` 之后不重发清单。关掉时模型手里还留着上一条档位清单，再打开若不重发，它会一直按旧档位用技能，直到下一次换档才纠正——`lastTier` 没清。
2. **时间行会被当成用户原话**。`IGNORED_SOURCES` 漏了 `skillgate-time`，截止备注里出现「帮我查」这类词就会触发切档。补上。
3. `state.json` 损坏后被默认值**静默覆盖**，旧档位与截止全丢且无痕迹。现在先把坏文件留成 `state.json.bad-<时间戳>`，再写新的。

**第二轮：真实语料回放。** `tools/replay.mjs` 把本会话 47 条人话按真实时间喂回去：

| 模式 | 结果 |
|---|---|
| 连续（一个会话按顺序） | 切档 7 次 |
| 独立（每条都当新会话第一句） | 5/47 会当场切档 |

7 次里有 5 次判定合理，2 次是误杀，**误杀源是同一个**：把触发词**写进句子里引用或讨论**也会命中。

- 10-27 02:36 讨论「第 4 问产不产词表」时引用了「交接文件」→ 切交付；
- 10-28 01:05 「这是我们的聊天日志和交接文件」→ 切交付（这条是实测，日志里有）。

另一处词表缺口：00:51「帮我看看现在有多少插件启用」被 `enter-work` 吃下，当时靠手动锁兜住了。`veto` 里有「几个技能」但没有「几个插件」。

**留给 v0.4 的两条结论**：

1. 字面匹配要做**引用剥离**——引号、书名号、代码块里的词不参与匹配。这比加置信度便宜，能去掉目前最主要的一类误杀。
2. `veto` 要从真实日志里补同义说法（「几个插件」这种用户真的说过的），而不是我编的。

**顺带确认的两件事**：`/tier off` 之后已注入的清单会留在历史里，直到上游重新发布或开新会话——所以「关掉完全恢复原样」这句话只在下一轮之后成立，已在 §8 的代价里补上。
